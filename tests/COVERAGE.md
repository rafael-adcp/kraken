# Conformance coverage of `PROTOCOL.md`

This is the clause-by-clause audit the project's spec-first process
([CONTRIBUTING.md](../CONTRIBUTING.md)) requires: every normative statement
(**MUST** / **MUST NOT** / **SHOULD** / **SHOULD NOT** / **RECOMMENDED**) in
[`PROTOCOL.md`](../PROTOCOL.md) is mapped to the test(s) that pin it, or marked
as a gap with a disposition. "The spec says it but no test pins it" is a
finding: the reference implementation passing is *not* evidence a third-party
implementation would.

Rows are anchored to the **section** that carries the clause, not to a line
number: line numbers drifted silently every time the spec grew a paragraph, and
a section survives the edit. Regenerate the clause list with:

```bash
grep -nE 'MUST|SHOULD|RECOMMENDED' PROTOCOL.md
```

## Legend

| Status | Meaning |
| --- | --- |
| ✅ **pinned** | A conformance case (`tests/conformance/`) or unit test (`tests/unit/`) fails if the behavior regresses. |
| 🧹 **lint** | Enforced deterministically by `scripts/lint-skills.sh` (`make lint`), not the conformance suite. |
| 🧠 **agent** | Worker *judgment* — exercised by the agent-behavior harness (`tests/agent/`, `make test-agent`), not the token-free conformance suite. |
| 🏗 **structural** | Guaranteed by construction: `kraken.py` has no code path that could violate it (e.g. no `close` subcommand, never reads assignees). |
| 📋 **operational** | A setup/deployment invariant about repositories or humans, outside any worker transition. |
| 🕳 **gap** | Mechanically pinnable but not yet pinned. Each has a follow-up issue. |

## §5 The claim algorithm — a lease on a git ref

| §5.1 the reader applies the expiry | A lease older than the TTL holds nothing; a reader **MUST** treat it as expired | ✅ pinned | `tests/unit/test_kraken.py` `LeaseStateTests` pins the decision as pure (live / past-TTL / boundary belongs to the thief / `live_leases` filter); `tests/conformance/test_lease_expiry.py` drives it end to end — a renewed lease blocks the claim, one past the TTL does not, a named `claim` reaches the same verdict as a drain, and the free `list-startable` read applies the same clock. |
| §5.1 unreadable clock | A lease whose commit (or date) cannot be read **MUST** be treated as expired — fail **open**, toward the steal | ✅ pinned | `tests/unit/test_kraken.py` `LeaseStateTests.test_an_unreadable_commit_fails_open_to_the_steal`; `tests/conformance/test_lease_expiry.py::test_an_unreadable_lease_commit_is_treated_as_expired` seeds a ref whose commit object does not exist and proves the task is stolen, not held forever. |
| §5.2 the generation ladder | The holder is the HIGHEST generation; taking a lease means CREATING the next one, so a first claim, a steal and a renewal are the same conflict-failing write. | §5.2 steal | N thieves on one expired lease produce **exactly one** winner, the losers writing nothing — and a steal cannot beat a concurrent renewal of the same lease | ✅ pinned | `tests/conformance/test_lease_steal_race.py`: three concurrent claims on one expired lease, released together by the stub's guard barrier — exactly one `0` and two `10`s, the surviving ref naming the winner, exactly one `lease-expired` note and one claim comment, no label touched by a loser. `test_a_renewal_and_a_steal_cannot_both_win` races the holder's renewal against a thief at the CAS itself (the stub's `GH_STUB_CAS_BARRIER`, which synchronizes ref creates rather than label reads): exactly one wins, and the loser is told — this is the race the ladder exists for, and it is unwinnable-by-both by construction, not by timing. |
| §5.2 lost verdict | The verdict **MUST** be available as an exit code, not as text to match | ✅ pinned | `tests/conformance/test_lease_steal_race.py::test_a_loser_reports_defeat_by_exit_code_alone` (a loss is exit 10 with an empty stderr); the same rule for writes is pinned by `tests/conformance/test_write_after_expiry.py`. |
| §5.3 prove the lease before writing | A worker **MUST** confirm it still owns the HIGHEST generation before the first write of escalation/delivery/release; not ours or gone → write nothing; ambiguous → re-check, never write. Renewal: `tests/conformance/test_heartbeat.py` (renewing a stolen or deleted lease is exit 10 and moves no ref) and the CAS race above. |
| §5.2 client-side filtering | Label filtering **SHOULD** be client-side for determinism | ✅ pinned | `tests/conformance/test_list_startable.py` asserts exact client-side-filtered output; `tests/conformance/test_list_startable_call_count.py` pins the O(1) call count (listing + the one claim-refs read) that client-side filtering enables, and that the comment threads §6 needs are hydrated for the held/leased few — exactly one batched call for 20 held tasks, and none at all on a queue where nothing is held — rather than riding the walk on every task; `tests/unit/test_kraken.py` `QueueWalkQueryTests` pins that the walk does not select comments, `CommentHungryTests` pins which tasks it fetches them for. |
| §5.2 the claim guard | Guard: a task held by `needs-decision`/`awaiting-merge` **MUST** be skipped without writing anything; a live lease that is not ours refuses too, as a loss | ✅ pinned | `tests/conformance/test_claim_held.py` (exit 11, zero writes, no git-data call on the two held labels; exit 10 on a live lease with or without a badge). |
| §5 CAS | Creating the claim ref is the arbiter: exactly one creator succeeds, HTTP 422 to the rest; the loser **MUST** back off writing nothing | ✅ pinned | `tests/conformance/test_claim_race.py` (two concurrent claims, exactly one `201`, the loser writes no comment and touches no label, the surviving ref names the winner); `tests/unit` `RefCasTests.test_claim_ref_create_maps_the_cas_outcomes` (201→won / 422→lost / other→fail) and `test_create_claim_commit_is_an_orphan_marker_commit`; `tests/conformance/test_claim_next.py` + `tests/unit` `ClaimNextIterationTests` (skip-on-loss forward-only; two concurrent `claim-next` workers claim two different tasks). |
| §5 thread independence | Ownership is the ref, not the comment thread: a thread of stale claim/reset markers neither blocks nor grants a claim, and the claim path reads no comments | ✅ pinned | `tests/conformance/test_claim_thread_independence.py` (stale markers never block; a live ref alone holds the task); `tests/conformance/test_claim_ignores_comments.py` (a 150-comment thread costs the claim zero comment reads, asserted on the stub call log). |
| §5 release the lease | Every terminal transition **MUST** delete the claim ref — every generation of it — **after** its comment/label writes; releasing early is an optimization, not an obligation | ✅ pinned | Escalate `tests/conformance/test_escalate.py`, deliver `tests/conformance/test_deliver.py`, release `tests/conformance/test_release.py` each assert the ref is gone; ordering-under-failure (ref delete last, task stays held) `tests/conformance/test_write_transition_failures.py`; `claim_ref_delete` idempotence (422 tolerated) `tests/unit` `RefCasTests.test_claim_ref_delete_tolerates_a_missing_ref`. |
| §5.3 one task at a time | A worker **MUST** work one task at a time; **MUST NOT** claim a second while holding a claim | ✅ pinned | `tests/conformance/test_claim_one_at_a_time.py`: `kraken.py claim` refuses (exit 11, writing nothing) a claim on a *different* issue while a `claim-<worker>.json` state file marks an open claim, and `claim-next` refuses on any open claim; re-claiming the *same* issue is permitted (the §5 network-failure caveat), and resolving the claim (deliver / escalate / release) clears the guard. State-file lifecycle: `tests/conformance/test_claim_state_file.py`. |

## §6 Lease renewal and the reconciler

| Clause | Normative text | Status | Pinned by |
| --- | --- | --- | --- |
| §6 renewal | A worker holding a lease **SHOULD** renew it every TTL/3, by creating the next generation; a refused renewal (422) means it was stolen from and it **MUST** stop | ✅ pinned (cadence 🧠 agent) | Cadence is worker behavior, but it is no longer prose the model has to remember: `next-action`'s envelope carries `renew_every_seconds`, `expires_at` and `renew_now`, and `then.renew` is the exact command (`tests/conformance/test_next_action.py`, `NextActionEnvelopeTests`).
